\section{Feci Guard: an external verifier}
\label{sec:guard}
If the model does not separate a false ``done'' from a true one, the check has to come from outside, and it should judge the final state rather than the agent's account of it, as $\tau$-bench does by scoring the final database state \citep{yao2024taubench}. Feci Guard is the simplest form of that check. When the agent calls \texttt{answer}, unless the answer declares the task infeasible, the guard takes a fresh screenshot and asks a separate verifier model to list every requirement of the task, to mark each one as met, unmet or not visible with its evidence, and to return a verdict. An \textsc{incomplete} verdict, which requires at least one requirement visibly unmet, refuses the answer and returns to the agent, as the answer's tool output, the missing requirement and a next action; the episode continues. A \textsc{complete} verdict, a timeout or an invalid output lets the answer through. At most two answers are refused per episode, and the third passes unchecked. A refusal always says what is missing, because blocking a false ``done'' without an explanation repaired none of the feasible false successes of the branching pilot (\S\ref{sec:online}). The verifier (Claude Sonnet through the Claude Code CLI alias \texttt{sonnet}, whose exact served version was not recorded, a fixed prompt and JSON schema, a 55\,s timeout) and the decision rule were frozen and registered before any evaluation. % source: data/local/feci_guard/README.md, PREREG.md (verifier sha256 0af76fdbacc72317...)

\paragraph{Offline, the verifier separates false from true successes.} On the same \gbEpisodes{} episodes of the original agent, judged from the final screenshot only, the frozen verifier detects \gbClaudeDet\% of the false successes and rejects \gbClaudeRej\% of the true ones, a gap of \gbClaudeGap{} points (95\% CI \gbClaudeGapCi, bootstrap over \gbTasks{} tasks; Table~\ref{tab:guard}). Holo-3.1-4B judging the same episodes detects \gbHoloDet\% and rejects \gbHoloRej\% (gap \gbHoloGap, \gbHoloGapCi), not distinguishable from chance, and the paired difference between the two judges is \gbClaudeVsHolo{} points (\gbClaudeVsHoloCi). A larger model of the same family, Holo4-27B with the same prompt as Holo-3.1-4B, rejects fewer true successes but detects no more false ones (gap \gbHolofourGap, \gbHolofourGapCi). With the verifier's own prompt and rule, Holo4-27B detects \gbHolofourfeciDet\% and rejects \gbHolofourfeciRej\% (gap \gbHolofourfeciGap, \gbHolofourfeciGapCi; \gbHolofourfeciNoVerdict{} calls without a verdict, counted as passes): \gbHolofourfeciVsHolo{} points above Holo-3.1-4B (\gbHolofourfeciVsHoloCi) and \gbHolofourfeciVsClaude{} below Claude (\gbHolofourfeciVsClaudeCi). At equal prompt, Claude's advantage comes mostly from the model; the prompt helps Holo4-27B by lowering its false rejections from \gbHolofourRej\% to \gbHolofourfeciRej\%, partly because its \gbHolofourfeciNoVerdictTrue{} calls without a verdict on true successes count as passes (\gbHolofourfeciRejValid\% on valid verdicts only). What a refusal is worth depends on the base rate. Among the tasks of the \textsc{test} split that the original, served by Modal, closes with \texttt{answer}, \fgBaseFsDone{} score 0 and \fgBaseTrueDone{} score 1 (\fgBasePartialDone{} partial scores left out), a false share $f\approx\fgBaseF$. With the verifier's detection $d$ and false rejection $r$ above, the precision of a refusal, $df/(df+r(1-f))$, is about \fgPrecision: roughly one refusal in four would hit a true success. This is an estimate, since the rates come from neighbouring distributions, not the same one. % source: data/local/online/results_test_gh_orig_modal_test/last_steps.jsonl (extract_last_steps.py), data/local/judge_bench/RESULT.json (figs/guard.py)
This is the measured basis for an external verifier, with three limits. One screenshot cannot show a saved file or a hidden setting, so detection cannot reach 100\%. Each judge ran once. And Claude may have seen public OSWorld tasks. % source: data/local/judge_bench/RESULT.json, REPORT.md (figs/guard.py)

\paragraph{A stronger judge.} Claude Opus, given the two screens before the answer and the list of actions, detects more false successes than the frozen verifier on a held-out half, \gvTwoDet{} against \gvOneDet{} (\gvDetDiff{} points, paired task-bootstrap 95\% CI \gvDetDiffCi; few discordant pairs, so the interval is approximate), with false rejections that rise by \gvRejDiff{} points (\gvRejDiffCi). The variant was selected on a development half and confirmed once on a held-out half drawn by task hash and committed before any test: on that half it detects \gvTwoDetPct\% (\gvTwoDet) and rejects \gvTwoRejPct\% (\gvTwoRej), against \gvOneDetPct\% (\gvOneDet) and \gvOneRejPct\% (\gvOneRej) for the frozen verifier, with a paired bootstrap over its \gvTasks{} tasks. A strict prompt demanding file evidence was rejected on the development half: it detected \gvStrictDet{} false successes but rejected \gvStrictRej{} true ones. The stronger judge has not been evaluated online. % source: data/local/feci_guard/v2/ (PROTOCOL.md, SPLIT.json, runs/, holdout_scores.jsonl), data/local/feci_guard/RESULTS.md (commit 171c962) (figs/guard.py)

\paragraph{Online, the guard halves false ``done'' without a measurable score change.} The guarded agent was run once on the \OgN{} tasks of the \textsc{test} split, under a rule and an analysis script committed before its results were read, and paired by task with the original served by the same Modal deployment on the same runners and harness. Its false ``done'' rate, a final \texttt{answer} on a task scored 0, falls from \OgFdBase\% to \OgFdGuard\% (\OgFdDiff{} points, 95\% CI \OgFdDiffCi), meeting the registered primary criterion (an upper 95\% bound below zero; the two servings of the original differ by less than two points, \OgpodFdBase\% against \OgFdBase\%). Its OSWorld score goes from \OgScoreBase{} to \OgScoreGuard{} (\OgScoreDiff{} points, \OgScoreDiffCi), which does not meet the secondary criterion (a lower bound above zero): we claim no score gain. The guard repairs \OgB{} tasks the original failed and loses \OgC{} the original solved, within the original's own run-to-run noise (served twice, it flips \ogNoiseDown{} tasks from 1 to 0 and \ogNoiseUp{} from 0 to 1), while avoiding \OgE{} false ``done''; the registered usefulness rule (repairs at least as many as losses, and fewer false ``done'') is met (net \OgB{} minus \OgC). The registration also planned a replication on the confirmation reserve and an online run of the escalation to Holo4-27B; neither was run. Two amendments were committed before any comparison: after the pod serving the agent failed, and before any guarded episode, the agent and the primary comparator moved to the Modal endpoint; and six tasks lost to an infrastructure failure were re-run once. Against the original served by the pod, the false ``done'' rate falls by \OgpodFdDiff{} points (\OgpodFdDiffCi) and the score changes by \OgpodScoreDiff{} (\OgpodScoreDiffCi). % source: data/local/online/ONLINE_GUARD_RESULT.json, .md, PREREG_ONLINE_GUARD.md, online_guard_analysis.py; recomputed from data/local/online/results_test_gh_orig_guard_claude, results_test_gh_orig_modal_test, results_test_gh_orig (figs/guard.py)

\paragraph{Replayed repairs.} In one end-to-end episode on a LibreOffice Impress task the original had failed with a false success, the guard refused the first ``done'' because the strike-through stopped mid-word, the agent followed the feedback and fixed the line, and the second ``done'' passed; the official checker still scored the task 0, because the remaining difference lies in the saved file, which the screen does not show. The guard also runs in our side-by-side live demonstration of the original and the guarded agent. A repair measure replays \fgRepairEpisodes{} recorded feasible false successes of the original up to their final answer and continues each twice per arm, with and without the guard, for at most \fgRepMaxSteps{} new steps, on the same server at the same time, scored by the official evaluator. Its protocol section was written before the arms were launched but first committed when about six branches had already finished, so the registration is self-declared; the exclusion rule depends only on the replay prefix, which runs before the continuation. \fgRepEpisodes{} episodes replay faithfully in all four branches (\fgRepExcluded{} excluded), \fgRepBranches{} branches per arm. With the guard \fgRepRepairedGuard{} of \fgRepBranches{} branches are repaired, without it \fgRepRepairedNog{} of \fgRepBranches. The paired difference per episode is \fgRepDiff{} points (95\% CI \fgRepDiffCi, bootstrap over episodes; with nine discrete differences, the upper bound varies between \fgRepDiffHiMin{} and \fgRepDiffHiMax{} with the bootstrap seed); \fgRepBetter{} episodes are better with the guard and \fgRepWorse{} worse, a sign test gives $p=\fgRepSignP$, and over all \fgRepEpisodesAll{} episodes the difference is \fgRepDiffAll{} (\fgRepDiffAllCi): the effect cannot be told apart from zero. The guard refused \fgRepRefused{} branches (\fgRepRefusals{} refusals in all), and \fgRepRefusedRepaired{} of them ended repaired, \fgRepRefusedRepairedPct\% (Wilson 95\% CI \fgRepRefusedRepairedCi\%), from two episodes: on \texttt{calc/1de60575}, 2/2 against 0/2 without the guard, the verifier saw that the pivot table sat on a sheet with the wrong name and the agent renamed it; on \texttt{writer/0b17a146}, 1/2. \texttt{\fgRepBothTask} succeeds in all four of its branches as soon as the agent answers: its recorded false success does not reproduce under replay, so it accounts for both repairs without the guard and two with it, and only \fgRepSpecific{} repairs are specific to the guard. The costs are visible too: \fgRepRefusedNoAnswer{} refused branches reach the step limit without answering again, \fgRepCapWrong{} pass at the refusal cap while still wrong, and on \fgRepWrongComplete{} episodes the guard accepts a wrong answer as complete in every branch. What is measured is a refusal plus coaching, since the feedback contains the verifier's suggested next action, not refusal alone. The refusal sometimes helps the agent repair, without statistical evidence at this stage. % source: data/local/feci_guard/repair/final/ (branches.jsonl, sha256 = rescue_bench provenance; results.json), RESULTS.md (independently recomputed), PREREG.md "Corrections after the independent review" (figs/guard.py)

\paragraph{Escalating to a stronger agent.} The same twelve recordings were replayed with a different policy: when the guard refuses the original answer, the episode is handed, with the answer and the verifier's feedback in its history, to a stronger agent, Holo4-27B, for at most \rbMaxNew{} new steps; the control hands every episode to Holo4-27B at the same point, without the guard. This contrasts the whole gated handoff with the stronger agent alone, not feedback alone, and the protocol was registered before any Holo4 sample. On the \rbPrimEpisodes{} episodes whose replay is valid in all four branches, the official score is 1 in \rbGuardSucc{} branches with the guard against \rbCtrlSucc{} without it (\rbGuardAfterAction{} against \rbCtrlAfterAction{} after a new action), a paired difference of \rbPrimDiff{} points (95\% CI \rbPrimDiffCi, bootstrap over episodes; \rbBetter{} episodes better, \rbWorse{} worse). The result holds with a stricter replay check (\rbStrictEpisodes{} episodes, \rbStrictDiff, \rbStrictDiffCi) and with all \rbAllEpisodes{} episodes (\rbAllDiff, \rbAllDiffCi). After an actual refusal, \rbRefRepaired{} branches are repaired after a new action. This is a replay measurement: escalation to Holo4-27B was not run online, and the change it predicts on the \textsc{test} split, \rbPredLo{} to \rbPredHi{} points depending on the unmeasured cost of a wrongly refused true success, is a prediction. % source: data/local/rescue_bench/RESULT.json, REPORT.md, PREREG.md, FINAL_REVIEW.md (independent numerical review PASS) (figs/guard.py)
